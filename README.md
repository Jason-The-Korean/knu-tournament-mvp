# KNU ARENA

경북대학교 학생을 위한 스포츠·e스포츠 대회 플랫폼 MVP입니다. 2026년 11월 14일 해커톤 시연을 목표로 LoL 팀 신청, 대진표, 양 팀 결과 확인, 일정 합의와 최소 계정 인증을 구현했습니다.

## 실행

Node.js 22.13 이상이 필요하며 Node.js 24.15.0에서 확인했습니다. Node.js 내장 HTTP·SQLite·crypto만 사용해 앱용 라이브러리 설치는 필요하지 않습니다.

```powershell
cd "C:\새 폴더\knu-tournament-mvp"
npm.cmd start
```

http://127.0.0.1:3000 에 접속합니다. 기존 서버가 실행 중이면 그 터미널에서 Ctrl+C 후 다시 시작해야 새 인증 API가 반영됩니다. PowerShell에서는 npm.cmd를 사용하면 스크립트 실행 정책을 변경할 필요가 없습니다.

```powershell
npm.cmd run dev
npm.cmd test
```

개발 모드는 서버 파일 변경 시 재시작하며 화면 변경은 새로고침합니다. 테스트는 별도 임시 DB를 사용합니다. 실제 scrypt와 로그인 요청을 검사하므로 수십 초가 걸립니다.

다른 포트가 필요하면 다음과 같이 실행합니다. 같은 브라우저에서 동일 호스트의 포트만 바꾸면 쿠키가 공유될 수 있으므로 다른 계정 시연은 별도 브라우저 프로필을 사용하세요.

```powershell
$env:PORT = '3001'
npm.cmd start
```

서버는 127.0.0.1에만 연결되고 Host는 localhost/127.0.0.1만 허용합니다. 공개 배포 설정이 아닙니다. 로컬 HTTP에서는 Secure 쿠키를 강제하지 않습니다. HTTPS 배포 전에는 SESSION_COOKIE_SECURE=1과 실제 TLS 종료를 구성해야 하며, 서버는 임의 X-Forwarded-Proto를 신뢰하지 않습니다.

## 계정과 권한 (현재 6단계 기준)

화면에서 회원가입 후 로그인할 수 있습니다. 가입 아이디는 영문·숫자·밑줄 3~32자이며 비밀번호는 12~128자입니다. 계정 생성은 학교 이메일 인증과 다릅니다. 경북대 소속, 실제 대표자 이름, Riot 계정 소유권은 검증하지 않습니다.

| 작업 | 권한 |
| --- | --- |
| 대회 목록·공개 대진표·결과·공식 일정 조회 | 비로그인 포함 누구나 |
| 새 대회 생성 | 로그인 사용자. 생성 계정이 개최자가 됨 |
| 참가 신청 | 로그인 사용자. 신청 계정이 대표자가 됨. 같은 대회에서 한 팀만 대표 가능 |
| 모집 마감·대진표 최초 생성·일정 규칙 최초 설정 | 해당 대회의 개최자만 |
| 팀 자격 일정 제안·결과 제출·일정 동의/거절 | 해당 경기에서 자기 팀을 대표하는 로그인 계정만 |
| 개최자 자격 일정 제안 | 해당 대회 개최자만. 팀의 동의를 대신할 수 없음 |
| 확정 일정 변경 | 새 제안에 해당 양 팀이 다시 동의하고 검증 통과 시 일반 변경 1회 |
| 기존 소유자 미연결 데모 변경 | 누구에게도 허용하지 않음. 읽기 전용 |

요청 본문에 다른 사용자·개최자·대표자 ID를 넣어도 소유권으로 사용하지 않습니다. 인증된 세션과 DB 소유권을 서버에서 비교합니다. 팀 ID를 위조한 상대 팀 결과/동의는 403입니다. 로그인 누락·만료는 401, CSRF 실패·권한 부족은 403, 업무 규칙 충돌은 409입니다.

화면은 내 권한의 입력만 보여주지만 UI 숨김은 보안 경계가 아닙니다. 서버가 모든 쓰기 요청을 다시 검증합니다. 다른 계정의 변경은 '최신 상태 새로고침' 버튼이나 브라우저 새로고침으로 확인합니다.

팀 상세 명단과 대표자 이름은 개최자 및 해당 팀 대표자에게만 제공합니다. 일반 조회에는 팀 ID·이름·승인 상태만 제공합니다. 비밀번호 해시·세션 저장값은 API로 반환하지 않습니다.

## 비밀번호·세션·CSRF

- 비밀번호는 계정별 무작위 16바이트 salt와 scrypt(N=32768, r=8, p=3, 64바이트 키)로 해시합니다. 평문 비밀번호를 DB·로그·소스에 저장하지 않습니다.
- 해시는 비동기로 계산하고 동시에 2건까지 처리합니다. 회원가입·로그인은 IP/아이디별 횟수를 제한하며 제한 정보는 SQLite에 저장합니다.
- 세션 ID는 32바이트 난수입니다. DB에는 ID의 SHA-256만 저장합니다. 세션의 사용자와 만료를 요청마다 확인합니다.
- 로그인 시 세션 ID·CSRF 토큰을 회전하고 이전 세션을 폐기합니다. 로그아웃은 서버 세션도 폐기합니다. 만료는 발급 후 8시간이며 재시작 후에도 유지됩니다.
- knu_session 쿠키는 HttpOnly, SameSite=Strict, Path=/, Max-Age를 사용하고 Domain을 지정하지 않습니다. HTTPS/명시적 Secure 설정 시 Secure도 추가합니다.
- 익명 세션을 포함해 세션에 묶인 CSRF 토큰을 발급하고 모든 POST의 X-CSRF-Token을 검사합니다. Origin과 Sec-Fetch-Site도 확인합니다. 토큰은 브라우저 메모리에만 두며 localStorage에 저장하지 않습니다.
- JSON만 허용하고 요청 크기를 제한합니다. CSP, nosniff, frame-ancestors, Referrer-Policy도 설정합니다. 정적 파일은 지정된 public 자산만 제공하며 DB/.git/auth.js는 제공하지 않습니다.

자세한 점검 및 한계는 SECURITY_REVIEW.md에 있습니다.

## 기존 DB 보존·이전 정책

서버 최초 실행 시 data/tournament.sqlite를 만들며 기존 파일이 있으면 그대로 사용합니다. 인증 스키마는 다음 테이블을 추가할 뿐 기존 대회·팀·대진표 JSON을 일괄 수정하지 않습니다.

- users: 아이디, 표시 이름, salt, 비밀번호 해시
- sessions: 세션 ID 해시, 사용자, CSRF, 만료
- auth_limits: 인증 요청 제한
- tournament_owners: 대회와 개최자 연결
- team_owners: 팀과 대표 계정 연결. 대회/계정 유일 제약

이전 대회·팀에 이름이나 Riot ID가 같다는 이유로 소유자를 붙이지 않습니다. 기존 소유자 미연결 대회는 읽기 전용 데모로 표시합니다. 자동 가져오기와 임의 소유권 획득 API는 제공하지 않으며 기존 /api/import는 410입니다. 이전 localStorage 원본도 삭제하지 않습니다.

시연에서는 새 계정으로 새 대회를 만들고 대표자 계정으로 새 팀을 신청하세요. 기존 데모를 지우거나 계정을 자동 연결할 필요가 없습니다. 실제 기존 대회 소유권 이전은 외부 증거로 신원을 확인한 뒤 별도 오프라인 절차를 설계해야 하며 이번 버전에는 넣지 않았습니다.

변경 검증은 운영 DB의 일관된 복제본에 스키마를 적용하여 tournaments/teams/brackets 원문을 비교했습니다. 기존 7개 대회, 22팀, 5대진표 및 그 안의 결과·일정이 동일했고 소유권 자동 지정은 0건입니다. 테스트 전후 운영 DB 파일 해시도 동일했습니다. 원본 운영 DB에 새 스키마가 적용되는 시점은 최신 서버를 재시작할 때입니다. data/는 Git 제외 대상이지만 로컬 파일 백업과 접근 통제는 별도로 필요합니다.

## 유지되는 운영 규칙

### STEP 1: 신규 대회의 모집 마감 일시

신규 생성은 기존 date(대회 날짜)를 유지하면서 startsAt(대회 시작)과 recruitEndAt(모집 마감)을 필수로 받습니다. 생성 화면의 날짜·시작 시간·모집 마감은 브라우저 시간대와 무관하게 KST로 해석하며, 서버에는 시간대를 포함한 UTC ISO 문자열로 저장합니다. 서버에서 마감 > 현재 시각, 마감 ≤ 시작, 시작의 KST 날짜 = date를 검사합니다. 일정 규칙은 계속 선택 사항이며 활성화하거나 나중에 최초 설정하면 scheduling.startsAt과 startsAt이 같아야 합니다.

참가 신청 시 트랜잭션 안에서 서버 시각을 다시 확인하며 현재 시각 ≥ recruitEndAt이면 409로 거절합니다. 정원·ID 중복·인증 검증과 정원 충족/사전 공지된 친선 조기 마감 조건은 유지합니다. 최소 2팀 미만의 수동 마감은 여전히 거절합니다. 모집 마감 경과는 목록·상세를 불러오거나 새로고침할 때 '모집 마감'으로 표시하고 진행 예정 필터에 포함합니다. 백그라운드 타이머·자동 상태 저장·취소·자동 대진 생성은 없습니다.

기존 JSON에 recruitEndAt이 없으면 기존 date·정원·상태 정책을 그대로 사용하고 임의의 시작/마감 값을 저장하지 않습니다. 기존 필드가 없는 목록에는 미설정/기존 정책 안내를 표시합니다. 스키마 변경 없이 신규 대회 JSON에만 필드를 추가했습니다. 테스트 전용 now 함수는 서버를 생성하는 코드에서만 주입 가능하며 HTTP 입력으로 시간을 바꾸는 API는 없습니다. DB/OS 시계는 변경하지 않습니다.

- 대회 정원 2~8팀. 팀은 정확히 Riot ID 5개, 대표자 인덱스 0~4를 입력합니다. 학교·Riot 소유권 인증은 미제공입니다.
- 서버가 ID 형식·동일 팀/대회의 ID 중복·팀명 중복·정원·모집 상태를 검사하고 선착순 자동 승인합니다.
- 모집 마감은 최소 2팀이며 정원 도달 또는 date 경과 시 가능합니다. 친선 조기 마감은 생성 시 공지한 최소 팀 수 조건에서만 가능합니다.
- 대진은 crypto.randomInt 기반 Fisher–Yates로 한 번 생성합니다. BYE끼리 붙지 않으며 BYE는 실제 경기 승리로 집계하지 않습니다.
- 경기 결과는 각 대표자가 별도로 제출합니다. PENDING → AWAITING_CONFIRMATION 또는 DISPUTED → CONFIRMED. 승자와 점수가 모두 같아야 확정합니다.
- Bo1은 1:0/0:1, 결승 Bo3는 2:0/2:1/0:2/1:2입니다. API score 배열은 슬롯 순서이며 제출 팀 기준으로 뒤집지 않습니다.
- 확정 전 수정은 이력에 남고 확정 후 수정·중복 처리는 차단합니다. 결과 확정과 nextMatchId/nextSlotIndex 진출을 하나의 트랜잭션으로 처리합니다. 결승은 championTeamId를 저장합니다.
- 일정은 대회 scheduling의 시작/종료, rounds(8/4/2강)의 기간, maxConcurrent(1~4경기)를 사용합니다. 기존 미설정 대회는 소유자 미연결이면 규칙 설정도 읽기 전용입니다.
- 새 대회 규칙은 생성 시 또는 개최자가 최초 1회 설정합니다. 규칙 변경 기능은 없습니다.
- 후보와 공식 일정은 별도이며 각 팀의 명시적 동의가 필요합니다. 동의 기한을 기다리지 않고 양쪽 동의 시 검증합니다. 선행 경기 일정부터 확정해야 후속 경기를 공식 확정할 수 있습니다.
- Bo1 90분/Bo3 210분은 편성용 예상 시간입니다. 실제 강제 종료·자동 몰수패·자동 일정 변경을 하지 않습니다.
- 대회/라운드 안에 예상 종료까지 들어가야 하며 팀 중복, 최대 동시 경기 수, 선후행 순서를 검사합니다. 종료=다음 시작은 겹침이 아닙니다.
- 후보가 거절되거나 충돌하면 공식 일정과 변경 횟수는 그대로입니다. 양 팀 재동의 후 변경 성공만 1회 차감합니다.

## API

GET /api/auth/session은 사용자와 CSRF 토큰을 반환합니다. 새 브라우저는 익명 세션 쿠키를 받습니다. POST /api/auth/register, /api/auth/login, /api/auth/logout이 가입·로그인·로그아웃입니다. 로그인/가입에도 먼저 받은 세션 쿠키와 CSRF가 필요합니다.

공개 조회는 GET /api/tournaments입니다. 항목별 permissions는 현재 세션의 manage, teamIds, legacyReadOnly를 표시합니다. 이 값은 서버가 계산하며 클라이언트 입력을 신뢰하지 않습니다.

로그인+CSRF가 필요한 POST:

```text
/api/tournaments
/api/tournaments/:id/teams
/api/tournaments/:id/close
/api/tournaments/:id/bracket
/api/tournaments/:id/schedule-rules
/api/tournaments/:id/matches/:matchId/results
/api/tournaments/:id/matches/:matchId/schedule-proposals
/api/tournaments/:id/matches/:matchId/schedule-proposals/:proposalId/consent
/api/tournaments/:id/matches/:matchId/schedule-proposals/:proposalId/decline
```

## 통합 시연 준비

1. 최신 서버를 재시작하고 브라우저에서 개최자 계정을 직접 가입·로그인합니다. 실제 비밀번호를 문서나 소스에 적지 마세요.
2. 다른 Chrome 프로필 또는 별도 브라우저 세션에서 대표자 계정을 각각 만듭니다. 같은 시크릿 세션의 창 여러 개는 쿠키를 공유하므로 독립 계정 검증에 적합하지 않습니다.
3. 개최자가 대회와 시간 규칙을 생성합니다. 대표자들이 각자의 세션으로 자기 팀을 신청합니다.
4. 개최자가 모집을 마감하고 대진표를 생성합니다. 3팀으로 시연하면 BYE와 실제 다음 라운드 진출도 확인할 수 있습니다.
5. 해당 경기 대표자가 일정을 제안하고 두 대표자가 각각 동의합니다. '최신 상태 새로고침'으로 상대 상태를 확인합니다.
6. 각 대표자가 결과를 제출합니다. 불일치 시 분쟁, 수정 후 일치 시 자동 진출을 확인합니다. 결승 결과까지 제출하면 우승팀이 표시됩니다.
7. 새로고침·서버 재시작 후 로그인과 결과·일정이 유지되는지 확인합니다. 재시작 자체가 로그아웃은 아닙니다.

자동 시연은 저장소 밖 ../browser-test-tools/ui-regression-browser.mjs입니다. 독립 Chrome 컨텍스트, 별도 SQLite, 임시 localhost 서버로 실행하며 비밀번호는 실행 시 난수로 생성하고 보고서/소스에 기록하지 않습니다. 테스트 DB에는 해시만 있습니다. 재실행 시 새 격리 DB를 만들며 운영 데이터는 변경하지 않습니다. 결과·화면·테스트 DB는 ../browser-test-tools/results/stage6-*에 보존합니다. 도구 폴더의 Playwright는 앱 의존성이 아닙니다.

이전 stage4/stage5 브라우저 스크립트는 인증 전 API용 기록입니다. 현재 UI 통합 검증은 ui-regression-browser.mjs를 사용하세요. stage6-browser.mjs는 로그인 영역이 모달로 바뀌기 전 기록입니다. 기존 1~5단계 자동 테스트는 실제 세션을 발급하는 테스트 클라이언트로 갱신했습니다. test-support의 소유권 지정은 이전 형태의 격리 테스트 픽스처만을 위한 코드이며 서버의 인증 우회 모드가 아닙니다.

## KNU ARENA UI: 1차 — 메인과 탐색

팀에서 제공한 로고와 붉은 강조색을 사용합니다. 홈·친선·경쟁·안내 내비게이션, 상태·유형·참가 범위 복합 필터와 이름 검색은 실제 API 데이터를 사용하며 AND 조건으로 함께 작동합니다. PC 3열, 중간 화면 2열, 모바일 1열입니다.

상태는 우승팀 확정 → 종료, BYE 외 경기 결과 제출·분쟁·확정 기록 존재 → 진행 중, 기존 참가 가능 조건 충족 및 읽기 전용 아님 → 접수 중, 나머지 → 진행 예정 순서로 계산합니다. 날짜만으로 실제 경기 시작·종료를 추정하지 않습니다. 진행 예정에는 모집 마감·정원 충족·대진 생성·기존 읽기 전용 대회가 포함됩니다.

새 대회 JSON에 선택적 competitionType(friendly/competitive), participationScope(open/department)를 저장합니다. 기존 friendly는 친선으로 표시하되 standard를 경쟁으로 추정하지 않습니다. 없는 유형·범위는 '미설정'으로 표시하고 특정 필터에서 제외합니다. 기존 레코드나 DB 스키마는 변경하지 않습니다. 학과 대항 선택은 표시용이며 실제 소속을 인증하지 않습니다.

설정 메뉴에서 라이트/다크를 전환하며 localStorage의 knu-arena-theme-v1에 저장합니다. 저장값이 없으면 OS 설정을 따릅니다. 저장소 차단 시 현재 전환은 가능하지만 저장 실패를 안내합니다. 알림 버튼은 미제공 안내만 표시합니다.

## KNU ARENA UI: 2차 — 관심 대회와 안내·규정

관심 대회는 localStorage의 knu-arena-favorites-v1에 ID만 저장합니다. 로그인 없이 같은 브라우저·사이트 주소에서 유지되며 계정·기기 간 동기화되지 않습니다. 공용 브라우저의 다른 계정에도 같은 목록이 보이며 브라우저 데이터 삭제 시 사라집니다. 손상된 저장값은 덮어쓰지 않고 오류를 안내합니다.

안내·규정은 기존 5단계 서비스 이용 순서와 공통 임시 운영 규정 PDF를 분리합니다. PDF는 학교 공식 규정이 아니며 계획·검토 항목이 현재 기능이나 확정 정책을 의미하지 않습니다. 다른 게임·공식 랭킹·학교 이메일/Riot 인증·자동 몰수패는 제공하지 않습니다.

로그인/가입 모달과 원래 개최·참가 작업 복귀, Escape·Tab·포커스 복원을 유지합니다. 로그인 계정 정보와 로그아웃은 계정 메뉴에 있습니다. 서버의 인증·권한·CSRF 검사는 유지합니다.

## 로고 자산

public/assets/knu-arena-logo.png와 knu-arena-logo-dark.png는 팀이 제공한 원본 PNG를 기반으로 합니다. 원본 파일은 작업 폴더의 knu-arena-logo-source.png.PNG이며 수정하지 않았습니다. 본 로고에서 떨어진 상단 곡선 조각, 밝은 배경과 여백만 픽셀 처리하고 KNU의 뿔·무늬·얼굴 및 ARENA 글자와 하단 선은 다시 그리지 않았습니다. 가장자리의 밝은 바탕 혼합색은 투명도로 정리했습니다.

기본 PNG는 빨강/검정을, 다크용 PNG는 같은 형태의 빨강/밝은 ARENA를 사용합니다. 두 파일은 437×109이며 CSS의 data-theme 선택자로 즉시 전환합니다. 데스크톱 폭 230px, 모바일 160px, 360px 이하 116px로 원본 비율을 유지합니다. 로고 링크는 홈으로 이동하며 접근 가능한 이름을 제공합니다. 원본 자체가 작은 래스터이므로 초고해상도 확대나 진짜 벡터의 선명도를 보장하지 않습니다.

축약 KNU 아이콘과 실제 SVG 벡터화는 별도 후속 작업입니다. 겹치는 KNU/ARENA 경계를 임의로 잘라 새 심벌을 만들지 않았으며, 현재 favicon 동작은 유지합니다. 학교 공식 교표를 결합하지 않았고 하단의 독립 학생 프로젝트 안내도 유지합니다. 서버 변경은 PNG 두 경로의 명시적 정적 파일 허용뿐이며 인증·CSRF·DB 구조는 변경하지 않았습니다.

## 대회 상세 페이지 — 1차

기존 #detail/대회ID 라우팅과 브랜드 배너를 유지합니다. 스티키 메뉴는 대회 홈·공지사항·대진/일정·참가자·영상·문의게시판·대회규정 중 선택한 탭만 표시합니다. 메뉴는 position: sticky, 제목 이동은 scroll-margin-top을 사용합니다. 글로벌 헤더와 겹치지 않으며 모바일 가로 스크롤 및 화살표/Home/End 키 전환을 지원합니다. 참가 신청 폼은 홈 탭에 있으며 기존 로그인 후 복귀를 유지합니다.

서버가 이미 공개하는 정보만 표시합니다. 개최자의 공개 이름과 별도 모집 시작/종료 일시는 저장·제공되지 않아 그 사실을 표시합니다. 경기 예정일은 date, 경기 기간·라운드 기간은 scheduling, 확정 경기는 bracket의 schedule을 사용합니다. 배너 이미지 필드는 없으므로 독립적인 브랜드 색상 배너를 사용합니다. 참가자 개인정보는 기존 API의 개최자·해당 대표자 공개 정책을 유지합니다. 공지·영상·문의는 실제 서버 기능이 없어 준비 중/미제공으로 안내합니다.

### 공통 규정 PDF

기존 Downloads/LoL_대학생_토너먼트_임시_운영규정집_v0.2.pdf를 바이트 변경 없이 public/assets/rules/common-draft-v0.2.pdf에 복사했습니다. 문서 표지의 상태는 v0.2 회의 검토용·규정 제정 전 초안이며 학교 공식 규정으로 표시하지 않습니다. 원문 SHA256은 04659aebcbdc2422539eab1d5cc839671ffa28378257c1974513b55f87c98ebb입니다. 문서를 새로 작성하거나 규정을 확정하지 않았습니다.

GET /api/rules는 파일 존재와 PDF 시그니처를 확인해 available, title, version, draft, url을 반환합니다. 미존재 시 available=false이며 UI는 링크 대신 준비 안내를 표시합니다. GET/HEAD /assets/rules/common-draft-v0.2.pdf는 공개 열람, ?download=1은 attachment 다운로드입니다. 메인 안내와 모든 대회 상세가 같은 문서를 사용합니다. PDF 업로드나 대회별 문서 관리 기능은 없습니다.

미리보기는 버튼을 눌러 같은 출처 iframe으로 열며, 미지원 브라우저는 항상 제공되는 새 탭/다운로드 링크를 사용할 수 있습니다. HTML의 object-src 차단과 외부 frame-ancestors 차단은 유지하고 PDF 응답만 같은 출처 임베드를 허용합니다. PDF 원문 색상은 두 테마 모두 유지합니다.

규정 동의 체크박스, 서버 동의 검증·이력 저장은 2차 범위로 이번에 추가하지 않았습니다. 기존 신청 검증·로그인 후 복귀·결과·일정 권한은 그대로입니다. 기존 SQLite 레코드와 스키마는 변경하지 않았습니다.

## 대진/일정 UI

결승 방식 표시는 저장된 bracket.finalFormat을 우선하고 없으면 대회의 finalFormat을 사용합니다. 유효한 Bo1/Bo3가 없으면 '경기 방식 미설정'으로 안내하며 DB 값을 채우지 않습니다. 기존 점수·일정 계산의 호환 기본값은 변경하지 않았고, 미설정 결승의 일정 안내에는 기존 계산 기준임을 구분해서 표시합니다.

대진/일정 안에서 대진표와 경기 일정 하위 탭을 제공합니다. 대진표는 기존 rounds, 경기 id, nextMatchId, nextSlotIndex만 사용해 가로 라운드와 연결선을 그립니다. 빈 슬롯은 미정, 부전승은 BYE로 표시하며 countsAsPlayed=false 진출을 경기 승리로 표현하지 않습니다. 경기/결과/일정 알고리즘은 변경하지 않았습니다.

확대·축소는 60~160%, 기본 배율은 100%입니다. 영역 안에서 가로·세로 스크롤과 모바일 터치 스크롤을 지원합니다. 팀 이름은 클릭 시에만 상세 모달을 열며, 기존 API가 허용한 대표자·선수 정보만 표시합니다. 공개 조회에서 숨겨진 Riot ID를 별도로 요청하거나 추정하지 않습니다. 모달을 닫아도 배율과 대진표 스크롤 위치를 유지합니다.

경기 상세에는 실제 라운드·방식·결과 상태와 기존 결과 입력 폼이 있으며, 일정 화면에는 공식 일정·제안·동의·충돌 안내와 기존 운영 기간 설정을 배치합니다. 경기 상세에서도 같은 일정 폼에 접근할 수 있습니다. 권한 있는 개최자/대표자에게만 기존 조작 폼이 제공되며 서버 검증은 그대로입니다. 외부 라이브러리는 추가하지 않았습니다. 전체 화면 모드는 이번에 추가하지 않았습니다.

## 미구현·남은 한계

학교 이메일 인증, Riot 소유권/실제 경기 증명, 공동 개최자, MFA, 비밀번호 재설정·변경, 전체 기기 로그아웃, 운영 장애 예외 연기, 알림, 자동 추천은 없습니다. 로그인된 계정의 권한은 확인하지만 그 사람이 실제 학생인지 확인하지는 못합니다. 일정 충돌은 해당 대회 내부의 예상 시간 기준입니다. 공개 배포 전에는 HTTPS·계정 복구·모니터링·추가 DoS 방어와 개인정보 정책 점검이 필요합니다. 이 버전은 로컬 해커톤 MVP입니다.
